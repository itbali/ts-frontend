# Habit Tracker - TypeScript Course (Starter Template)

## 🎯 Добро пожаловать!

Это стартовый проект для курса TypeScript. Вы будете реализовывать типизацию и интеграцию с backend API.

## 🚀 Быстрый старт

```bash
cd frontend-starter
npm install
npm run dev
```

Откройте http://localhost:5173

**Приложение уже работает!** Оно использует mock данные, чтобы вы могли сразу видеть результат своей работы.

## ✅ Что уже готово

- ✅ **UI полностью работает** - вся логика отображения готова
- ✅ **Mock данные** - приложение работает без backend
- ✅ **Структура проекта** - все файлы на своих местах
- ✅ **Базовая типизация** - есть заготовки с подсказками

## ⚠️ Что нужно реализовать

### Модуль 1: Базовые типы 

**Файлы для работы:**

- `src/types/entities.ts` - определите интерфейсы для всех сущностей
- `src/types/api.ts` - создайте типы для API запросов/ответов

**Задания:**

1. Определите все интерфейсы (User, Habit, HabitLog, Category, Achievement)
2. Замените `any` в сервисах на правильные типы
3. Реализуйте type guards в `types/api.ts`

**Подсказки:**

- Смотрите комментарии с TODO в коде
- Используйте Swagger документацию: http://188.132.184.170.nip.io/docs#/

### Модуль 2: Сервисы с моками 

**Файлы для работы:**

- `src/services/habit-service.ts`
- `src/services/log-service.ts`
- `src/services/category-service.ts`
- `src/services/auth-service.ts`
- `src/services/analytics-service.ts`

**Задания:**

1. Замените `any` на правильные типы
2. Убедитесь что все функции типизированы
3. Добавьте обработку ошибок

**Текущее состояние:**
Сервисы работают с mock данными из `src/mocks/`. Это позволяет разрабатывать без backend.

### Модуль 3: API интеграция 

**Файлы для работы:**

- `src/api.ts` - HTTP клиент

**Задания:**

1. Улучшите функцию `request<T>`
2. Добавьте правильную обработку ошибок
3. Реализуйте обработку разных форматов ответов API
4. Замените mock реализации в сервисах на реальные API вызовы

**Подсказки:**

- API может возвращать `{ success: true, data: T }` или просто `T`
- Используйте токен из localStorage для авторизации
- Обрабатывайте HTTP ошибки (4xx, 5xx)

### Модуль 4: Валидация 

**Создайте файлы:**

- `src/utils/validators.ts`

**Задания:**

1. Реализуйте валидаторы для email, password, habit title
2. Добавьте валидацию перед отправкой на API
3. Покажите пользователю понятные сообщения об ошибках

### Основные endpoints:

- `POST /auth/login` - авторизация
- `POST /auth/register` - регистрация
- `GET /auth/me` - текущий пользователь
- `GET /habits/` - список привычек
- `POST /habits/` - создать привычку
- `DELETE /habits/{id}` - удалить привычку
- `GET /logs/` - список логов
- `POST /logs/` - создать лог
- `GET /categories/` - список категорий
- `GET /analytics/` - аналитика

## 💡 Советы

1. **Начните с типов** - определите все интерфейсы перед написанием кода
2. **Используйте TypeScript** - пусть компилятор помогает вам находить ошибки
3. **Тестируйте постепенно** - сначала с моками, потом с реальным API
4. **Смотрите в консоль** - там будут ошибки TypeScript и runtime
5. **Используйте Swagger** - там описаны все типы запросов и ответов

## 🎓 Прогрессия обучения

### Этап 1: Запуск 

```bash
npm install && npm run dev
```

Убедитесь что приложение работает с моками.

### Этап 2: Типы 

Определите все типы в `src/types/`. Приложение продолжит работать с моками.

### Этап 3: Сервисы 

Типизируйте сервисы. Приложение всё ещё работает с моками.

### Этап 4: API 

Реализуйте `api.ts` и замените моки на реальные вызовы. Теперь приложение работает с backend!

### Этап 5: Валидация 
Добавьте валидацию и улучшите UX.

## 🔍 Как проверить свою работу

1. **TypeScript компилируется без ошибок**

   ```bash
   npm run build
   ```

2. **Приложение работает с моками**
   - Можно создавать привычки
   - Можно отмечать выполнение
   - Можно удалять привычки

3. **Приложение работает с реальным API**
   - Данные сохраняются на сервере
   - После перезагрузки страницы данные остаются
   - Можно зарегистрироваться и войти
